# Veloce · Watch Together

Первая рабочая beta-версия персонального кинозала: FastAPI + WebSockets,
собственный интерфейс плеера + hls.js, PeerJS для голоса, камеры и экрана.
Сайт ещё не опубликован. Архив — исходный проект, а не готовая публичная ссылка.
Отдельный HTML-просмотрщик показывает только интерфейс и локальные действия.

## Что умеет эта версия

- Секретные комнаты по ссылке, до 6 участников. Один ведущий управляет просмотром;
  любой обладатель ссылки может взять управление.
- YouTube, VK Видео, Rutube (экспериментальный адаптер) через внешние плееры.
- Прямые HTTPS-потоки HLS (.m3u8), MP4 и WebM в собственном интерфейсе плеера.
- Одинаковый локальный файл у каждого участника: файл не передаётся на сервер.
- Поиск аниме в актуальном API AniLiberty (бывшая AniLibria), доступные эпизоды
  и разрешения. У этого источника своя озвучка, не все студии сразу.
- Опциональный KodikParser с ВАШИМ API-токеном: поиск, список переводов и прямой
  поток, если его использование разрешено владельцем источника. Автополучения
  токенов, обхода DRM, геоблокировок и платного доступа нет.
- Поиск метаданных фильмов через Kinopoisk Unofficial с ВАШИМ ключом.
  Видеопотоки — отдельно из media.json либо настроенного Kodik.
- Выбор озвучки, сезона, серии и качества из фактических данных источника.
- WebSocket play/pause/seek/change_source, ревизии источника против запоздалых
  событий, оценка серверного времени через ping/pong, anti-echo и исправление
  рассинхронизации при отклонении больше 1,5 секунды.
- Чат, реакции, голос, выключение микрофона, камера, демонстрация экрана.
- Тёмно-фиолетовый адаптивный интерфейс; при 390 px блоки в одной колонке.
- Динамическое свечение для доступных кадров HTML-video. Для iframe или
  недоступного canvas — декоративное фиолетовое свечение.

## Важно: отличия от идеализированного ТЗ

1. «Любое видео», «без лагов» и «все озвучки» гарантировать нельзя. Ограничения
   источников, кодеков, сети, рекламы и браузеров сохраняются.
2. В самом Veloce нет рекламных блоков. Рекламу YouTube/VK/Rutube мы не удаляем.
   Реклама, встроенная в сам поток поставщика, тоже может сохраниться.
3. KodikParser здесь **экспериментальный и опциональный**. Проверены реальные
   сигнатуры установленной версии 1.18.0, но сквозной тест с токеном не выполнен:
   пользовательский токен не предоставлен. Документированный метод этой
   библиотеки для прямых потоков ограничен сезоном 1 и максимум 720p. Другие
   сезоны следует выбирать отдельными релизами; произвольная поддержка сезонов
   и 1080p у Kodik не заявляется.
4. В AniLiberty доступны 480/720/1080p только если API выдал соответствующий URL.
   Заблокированные по географии или правам релизы возвращают ошибку без обхода.
5. Kinobox, Alloha, Videocdn не подключены: в ходе проверки не подтверждён
   стабильный контракт управления ими для синхронизации. iframe сам по себе
   НЕ даёт доступа к таймкоду. Вместо фиктивно работающих интеграций используется
   разрешение прямых потоков. Это не готовая библиотека всех фильмов.
6. Прямой поток должен работать в браузере у КАЖДОГО участника, разрешать CORS,
   иметь HTTPS и поддерживаемые кодеки. Некоторые URL истекают или привязаны
   к IP сервера: без разрешённого доступа со стороны клиентов они не заработают.
   Прокси для обхода этих ограничений в проекте нет. При истечении URL повторно
   выберите эпизод; автоматическое обновление подписанных URL не реализовано.
7. Screen Share передаёт картинку со своего устройства: это live-поток, а не
   синхронизация общего файла. Задержка ненулевая. Звук зависит от выбора
   вкладки/окна, ОС и браузера. DRM-видео может быть чёрным. Мобильные браузеры
   обычно не умеют начинать демонстрацию. Не транслируйте защищённое или чужое
   содержимое без разрешения.
8. PeerJS по умолчанию использует публичный сервер сигналинга. В сложных сетях
   для WebRTC нужен TURN; STUN не гарантирует соединение. При screen share
   WebRTC mesh отправляет отдельный поток каждому зрителю: нагрузка растёт.
9. Нет аккаунтов, истории просмотров, сохранённых друзей, постоянной БД и
   модерации. Это персональная beta, а не production-платформа.

## Быстрый локальный запуск

Нужен Python 3.12+ (проверено на Python 3.13). Node.js для запуска НЕ нужен.
Распакуйте архив и откройте терминал в папке с main.py.

### Windows PowerShell

```powershell
py -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python -m uvicorn main:app --host 0.0.0.0 --port 8000 --workers 1 --env-file .env --ws-max-size 65536 --log-level warning
```

### macOS / Linux

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
.venv/bin/python -m uvicorn main:app --host 0.0.0.0 --port 8000 --workers 1 --env-file .env --ws-max-size 65536 --log-level warning
```

Откройте http://localhost:8000. Для проверки откройте приглашение во втором
браузере/приватном окне. По умолчанию работают ссылки, файлы, аниме из AniLiberty
и чат, если соответствующие источники доступны из вашей сети.
Ключи не нужны для комнат, HLS-плеера, YouTube, VK и Rutube.

**localhost — только ваш компьютер, девушка из другой сети по нему не войдёт.**
Для просмотра на расстоянии разместите проект на облачном хостинге ниже.
Микрофон/камера/экран работают по HTTPS; localhost — специальное исключение.
Не открывайте index.html двойным кликом — backend так не запускается.

## Размещение без своего сервера

В архиве есть render.yaml и Dockerfile. Можно использовать облачный Web Service
с Python и постоянными WebSocket-соединениями, например Render.

1. Создайте собственный репозиторий GitHub и загрузите файлы проекта в корень.
   Не загружайте .env, API-токены или .venv. Включите отображение скрытых файлов,
   чтобы .gitignore тоже попал в репозиторий.
2. В Render создайте Web Service из этого репозитория (или Blueprint из
   render.yaml). Python 3.12+, команда сборки `pip install -r requirements.txt`.
3. Команда запуска:
   `uvicorn main:app --host 0.0.0.0 --port $PORT --workers 1 --ws-max-size 65536 --log-level warning`.
4. Получив HTTPS-адрес, задайте APP_ORIGIN точно этому адресу без завершающего
   слеша и заново разверните сервис. Если есть свой домен, используйте его.
5. При необходимости добавьте собственные ключи в Environment хостинга.
6. Откройте адрес, создайте комнату, отправьте ссылку девушке. У каждого при
   первом запуске видео может понадобиться нажать Play для звука.

Доступность бесплатного тарифа, лимиты и необходимость платёжных данных
проверяйте у хостинга. render.yaml указывает plan: free, но бесплатная работа
без ограничений не обещается. Сон/перезапуск сервиса может удалить комнату.
Обычный статический хостинг, GitHub Pages или открытый HTML не заменяют FastAPI.

**Обязательно 1 worker и 1 экземпляр приложения.** Состояние в памяти процесса:
несколько workers дадут разные комнаты. Для масштабирования нужны Redis/БД
и pub/sub. Комната и чат исчезают после перезапуска; пустые комнаты удаляются
через 6 часов. Лимиты памяти: 500 комнат, 6 участников, 100 сообщений на комнату.

## Контентные ключи и собственные фильмы

- `KINOPOISK_API_KEY`: собственный ключ Kinopoisk Unofficial. Только сервер.
- `KODIK_TOKEN`: собственный выданный провайдером токен, не чужой извлечённый.
- `ENABLE_KODIK_STREAMS=true`: включайте только при разрешении источника на
  разрешение прямых потоков. По умолчанию false. Без этого можно искать и
  смотреть список озвучек, но поток вернёт понятную ошибку.
- `ANILIBRIA_BASE`: по умолчанию https://aniliberty.top — актуальный сервер API.
- `MEDIA_CATALOG`: путь к вашему JSON-каталогу потоков (по умолчанию media.json).

Для своих фильмов перенесите структуру media.example.json в media.json. Ключ
первого уровня — строковый ID Кинопоиска, не случайное название. У каждой озвучки
есть seasons, у сезона episodes, у эпизода реальный разрешённый HTTPS URL.
Файл примера содержит заглушку домена и не открывает фильм без вашего URL.
Свою прямую ссылку также можно вставить без каталога кнопкой «Добавить видео».

## Голос, камера, экран и приватность

Кнопка «Подключить голос» запрашивает микрофон, кнопка микрофона выключает/включает
его, камера включается отдельно. Захват разрешений происходит только после
нажатия пользователем. Выход/потеря соединения останавливает локальные треки.
Не выдавайте доступ к камере/экрану, если не хотите передавать их участникам.

Сервер Veloce передаёт команды и состояние, а не сохраняет аудио/видео.
PeerJS передаёт WebRTC-медиа между участниками; при TURN оно ретранслируется.
Участники WebRTC могут узнавать сетевые адреса друг друга; сервер сигналинга
и поставщики контента видят соответствующие подключения. Внешний контент
загружается только после явного выбора; постеры — после запуска поиска.

Для TURN задайте ICE_SERVERS как однострочный JSON-массив. Конфигурация ICE
поступает в браузеры участников, поэтому постоянные пароли TURN не считаются
секретом браузерного клиента. В production используйте краткоживущие credentials,
добавив серверную выдачу у вашего TURN-поставщика. Заготовка не реализует их ротацию.
Собственный PeerServer настраивается PEER_HOST/PEER_PORT/PEER_PATH/PEER_SECURE.
Тестовый локальный запуск соединялся через публичный PeerJS.

## Локальные файлы

Каждый выбирает собственную копию одного и того же видео. Blob URL не передаётся
между участниками. Проверяются размер и SHA-256 первых/последних 1 MiB + размера;
это быстрый **частичный отпечаток, не полный хеш всего файла**. Такие проверки
не доказывают побайтовую идентичность. Для надёжной синхронизации используйте
действительно одинаковый файл, монтаж, дорожку и скорость 1×. Неизвестные кодеки,
MKV или некоторые аудиоформаты могут не поддерживаться браузером.

## Защита и ограничения

Ссылка комнаты — bearer-secret (случайные 144 бита). Любой с этой ссылкой может
войти, читать чат и управлять плеером. Это не защита аккаунтом. Не публикуйте
ссылку и не записывайте её в открытые логи. Оператор сервера имеет доступ к
комнатам в памяти. Код ограничивает Origin, размеры/частоту сообщений, количество
комнат/участников и HTTP-запросов; контент пользователей выводится через textContent.
Сервер не скачивает произвольные пользовательские URL и не является видеопрокси.

Перед открытым публичным запуском нужны авторизация, защита ключей от злоупотребления,
распределённый rate limiting, настройки reverse proxy и логов, квоты на TURN,
мониторинг, постоянное хранилище и проверка прав на распространение контента.
Сейчас это продукт для небольших доверенных компаний. Нельзя обещать отсутствие
атак, потери сообщений при обрыве или бесконечную работу бесплатного сервиса.

## API

- `POST /api/rooms` → room_id.
- `GET /api/config` → возможности и настройки PeerJS (без контентных токенов).
- `GET /api/anime/search?q=...&provider=all|anilibria|kodik`.
- `GET /api/anime/details?id=...&provider=anilibria|kodik&id_type=shikimori|kinopoisk`.
- `GET /api/anime/stream?id=...&provider=...&episode=1&translation=anilibria&quality=720&season=1`.
- `GET /api/movies/search?q=...&page=1`.
- `GET /api/movies/{kinopoisk_id}/sources`.
- `GET /api/movies/stream?id=...&translation=...&season=1&episode=1` для media.json.
- `WS /ws/{room_id}/{username}`. События: init, members, play, pause, seek,
  state, change_source, chat, reaction, take_host, peer_id, media, speaking,
  ping/pong. webrtc_signal доступен как расширение; PeerJS использует свой
  signaling, а peer_id распространяется только в комнате.
- Документация FastAPI: `/docs`; проверка здоровья: `/health`.

Для событий воспроизведения клиент передаёт time, playing и source_revision.
init/смена источника возвращают playback с серверным временем и ревизиями.
Только ведущий меняет playback/source. Необходимость ручного Play из-за autoplay
и ограничения iframe — нормальные состояния, а не обходимые ошибки.
