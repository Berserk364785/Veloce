# Проверка Veloce 0.2.0

## Автоматические серверные тесты

Python 3.13, FastAPI 0.146.0, httpx 0.28.1, pytest: **13 passed**.
Есть предупреждение upstream Starlette об устаревании интеграции TestClient
с httpx; падений тестов нет. Сценарии:

- Два WebSocket-участника, вступление, роль ведущего и передача управления.
- Смена источника, play/seek/state и пауза при выходе ведущего.
- Запоздалый heartbeat от старого источника не изменяет новый источник.
- Чат с HTML-строкой остаётся текстом; реакции доставляются.
- Изоляция неизвестной комнаты, отказ по чужому Origin.
- Валидация источников, запрет private IP / credentials / javascript URLs.
- Понятный ответ при отсутствии ключей, HTTP security headers.
- AniLiberty search/details/stream на контролируемых ответах.
- Географический/правовой запрет релиза не обходится.
- Выбор прямого потока из своего каталога, включая сезон 2.

## Chromium · два независимых browser contexts

Без необработанных JavaScript-ошибок в пройденных сценариях:

- Два участника подключились по одной ссылке.
- Сообщение с `<img onerror=...>` отображено как текст, без HTML-элемента.
- Прямой MP4 открылся в обоих браузерах; запуск, перемотка и пауза передались.
- Реакция появилась у второго участника.
- Отсутствующий KINOPOISK_API_KEY показан как конфигурационная ошибка.
- Одинаковый локальный файл загрузился независимо у обоих участников.
- Через публичный PeerJS получен удалённый аудиопоток и видеопоток камеры.
  Использованы **искусственные устройства Chromium**, не настоящие микрофоны.
- HLS-плейлист и сегменты через hls.js воспроизвелись у обоих участников.
  Использован синтетический ролик и перехваченный тестовый HTTPS-источник с CORS.
- Синтетический MediaStream (замена getDisplayMedia в тесте) передан через
  PeerJS другому участнику. Это проверка транспортного пути, не выбор реального
  окна в системном диалоге. Завершение очистило источник у обоих.
- Живой запрос к AniLiberty вернул HTTP 200 и 3 результата по `naruto`.
  Это проверка поиска, не гарантия работы каждого HLS URL у любых пользователей.
- При 390 px нет горизонтального переполнения. Проверены диалог добавления
  видео, пустой кинозал, каталог и активный экран на desktop/mobile.

## Не проверено / не заявляется

- Сквозное разрешение и просмотр Kodik с реальным токеном: токен не предоставлен.
- Живой поиск Кинопоиска с пользовательским ключом: ключ не предоставлен.
- Долгий совместный сеанс с каждым из YouTube/VK/Rutube в разных сетях.
  Реализованы API-адаптеры, но рекламные паузы/изменения API могут нарушать sync.
- Реальные микрофоны/камеры, системный диалог Screen Share, реальный системный
  звук, Safari/iOS, Android и TURN в сложных NAT-сетях.
- Нагрузочное тестирование, аудит production-безопасности, отказоустойчивость,
  длительные стримы и автоматическое обновление подписанных ссылок.
- Облачное размещение не выполнено; публичная ссылка на сайт не создана.

Нельзя интерпретировать локальные тесты как гарантию «без лагов» или
«все фильмы/озвучки без рекламы».
